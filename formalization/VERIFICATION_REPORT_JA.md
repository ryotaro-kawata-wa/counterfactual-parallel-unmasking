# arXiv 準備と Lean 検証の記録

検証対象は、push 済みの ICLR 原稿 `8a8c185375bd4de48c2ef52807da0c3cc00e15ac`
から体裁だけを変更した arXiv 版 `1507791fd7c1137c77ec139cc0b73b5765f1464b`。
数学的な TeX 本文は変更していない。実際に組版される 61 個の TeX 入力を
SHA-256 で固定し、変更を検出する検査を用意した。

## 今回の対象

台帳の 36 個の定理・命題・補題・系に対応する形式定理群を検証した。
25 個の定義・仮定は別途、原稿と形式化の対応を監査した。

- 実際の乱択 sampler の有限 TV/KL 上界、全経路の query/round/depth、
  成功経路での厳しい round 上界、公的な row selector の変更への不変性。
- 公開 cutoff の全範囲に対する主上界と、付録そのものの誤差配分。
  balanced cutoff による総呼出し数・並列深さの `o(N)`。
- commit の確率ベクトルと標本値の両方を観測できる算法に対する有限下界。
  任意の語彙ラベル、公開クラス、独立誤差半径、漸近較正まで接続。
- 比較 path の実際のクラス所属、TC/DTC の正確な公式、独立マスキングに
  基づく effective TC の線形上下界。情報量の定数は語彙数に依存しない。

原稿との対応確認中に、初期の形式化では commit の確率ベクトルを後続の
判断に渡していない点が見つかった。そのまま下界の適用範囲を広げず、
完全な観測インターフェース、出力分布と元の予算を保存する変換、
無料の現在履歴 readout を許しても成り立つ下界を証明して修正した。
これは形式化側の不足の修正であり、原稿の主張を弱める修正ではない。

`AuditAxioms.lean` は import された全プロジェクト宣言の推移的依存を調べる。
許す公理は `propext`、`Classical.choice`、`Quot.sound` のみで、
`sorryAx` や独自公理があれば失敗する。宣言数は論文の定理数ではない。
台帳内の Lean 参照が実在し、root から import されることも別検査する。


## 範囲の限界

Lean が検査するのは形式文とその証明であり、TeX を自動翻訳したものではない。
原稿との対応は `audit/INTERFACE_CORRESPONDENCE.md`、主定理の監査記録、
`audit/PATH_FINAL_CORRESPONDENCE.md` などで明示している。
任意の実装を controller 木へ変換する表現論、ラベルのない説明文、
実験の科学的妥当性、引用、外部論文の sampler 保証までを一括して
「Lean 検証済み」と呼ぶことはできない。参照論文の一般的な
`effective TC <= min(TC,DTC)` は仮定せず、この path の上界を直接証明した。

## 原稿を確定する順番

1. 数学的な主張・仮定・算法・資源と誤差の定義を固定し、対応台帳を作る。
2. その基準で Lean を進め、原稿と形式化のずれを監査する。
   導入・引用・表現の確認と体裁変更は並行してよい。
3. 数学的な修正が出たら、該当 TeX 入力の固定値と対応定理を一緒に更新する。
4. 最後に本文の説明・引用・実験との一致、著者情報、最終 PDF を確認する。

今回、高い推論能力が必要だったのは、形式文の対応、観測インターフェース、
適応的下界、条件付き情報量・積分を含む難しい証明の部分。
安定後のビルド再実行、台帳更新、軽い LaTeX 体裁修正は通常の設定で進められる。
原稿全体の文章を完全確定するまで Lean 開始を待つ必要はない。

## 統合先（2026-09-28 更新）

`codex/arxiv-preprint` に、最新原稿・実験コードと保存結果・完全な
`formalization/` を統合した。原稿には著者・所属・メール・謝辞を反映済み。
段落頭の字下げをなくして控えめな段落間隔を入れ、97 ページ版になった。
原稿、実験、Lean の入口はリポジトリ直下の `README.md` にある。
元の ICLR チェックポイントと Lean 検証ブランチの履歴も保持している。

元の数学的検証基準からの差分は、著者情報・謝辞・図3の表示上の単位・
段落の組版設定だけ。
元の 61 個の TeX 入力のうち 58 個は完全一致し、数学的な定義・定理・証明
ファイルはすべて変更していない。追加の謝辞を含む現在の 62 入力を固定した。
原基準は `audit/manuscript_basis_2026-09-26.json`、差分の監査は
`audit/ARXIV_RELEASE_BASIS.md` に保存した。

再現コマンドと正確な形式化範囲は `README.md` と
`audit/claim_inventory.json` を参照。GitHub への push と arXiv 投稿は別操作で、
arXiv への投稿は実施していない。
